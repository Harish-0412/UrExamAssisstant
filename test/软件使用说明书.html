第一章 软件概述

1.1 产品简介

过了喵（英文名称 Exameow）是一款基于人工智能技术的智能考试题目自动生成系统。本软件的核心目标是将先进的大语言模型（LLM）技术与教育场景深度结合，为用户提供一个高效、便捷、智能的出题辅助工具。用户只需上传包含学习内容的电子文档（如教材、课件、讲义、笔记等），系统即可自动解析文档内容，调用 AI 模型快速生成符合专业要求的各类考试题目。

在当今教育信息化快速发展的背景下，教师、培训人员和自主学习者面临着共同的挑战：高质量练习题的获取和制作成本高、周期长。传统手工出题方式要求出题者具备深厚的学科知识和出题经验，同时需要投入大量时间进行题目设计、干扰项构思、答案校验和解析编写。过了喵正是为了解决这一核心痛点而设计——它将出题过程中最耗时、最依赖经验的部分交由 AI 完成，让教育工作者能够将宝贵的时间和精力更多地投入到教学设计和学生互动等更高价值的活动中。

过了喵支持多达九种常见文档格式作为输入源，包括 PDF 便携式文档、Microsoft Word 文档（DOCX）、Microsoft Excel 电子表格（XLSX）、Microsoft PowerPoint 演示文稿（PPTX）、EPUB 电子书、ODT 开放文档、纯文本文件（TXT）、CSV 数据文件以及 HTML 网页文件。这种广泛的格式支持意味着用户可以上传几乎所有类型的电子学习资料，无需进行繁琐的格式转换预处理。在 AI 模型集成方面，过了喵兼容所有遵循 OpenAI Chat Completions API 格式规范的大语言模型服务，用户可以使用 OpenAI 官方 GPT 系列模型，也可以接入 DeepSeek、通义千问、智谱 GLM 等国产大模型，还可以通过 Ollama、vLLM 等工具连接本地部署的开源模型，实现完全的离线出题和数据零泄露。

过了喵提供覆盖全主流计算平台的多种使用方式。桌面端原生应用基于 Tauri v2 框架构建，支持 macOS、Windows 和 Linux 三大操作系统，安装包体积小巧、启动速度快。移动端应用支持 iOS 和 Android 系统，使用户能够在手机和平板上随时随地进行刷题练习。Web 网页版通过任意现代浏览器即可访问，是最低门槛的使用方式。Docker 容器化部署方案提供灵活的自托管选项，适合团队协作和企业内部使用。Cloudflare Workers 无服务器部署方案利用 Cloudflare 全球边缘计算网络实现低成本全球低延迟访问。系统内置完整的在线练习和智能错题管理功能，所有用户数据完全存储于本地设备，敏感配置采用 AES-256-GCM 加密保护。

1.2 核心功能

过了喵围绕"文档解析 → AI 出题 → 题库管理 → 在线练习 → 错题追踪"的核心流程，构建了以下主要功能模块：

（一）多格式文档智能解析：系统内置强大的文档解析引擎，支持 PDF、DOCX、XLSX、PPTX、EPUB、ODT、TXT、CSV、HTML 共九种主流文档格式的自动解析。PDF 文档处理通过读取 PDF 文件内部结构，定位文本流对象，提取页面文本内容并按阅读顺序重新排列。对于 DOCX 和 PPTX 等 Office 格式文档，解析引擎将文件作为 ZIP 压缩包打开，读取其中的 XML 数据文件并提取结构化内容。EPUB 电子书先解析 OPF 清单文件获取目录结构，再按顺序提取各章节的 XHTML 内容。所有提取的原始文本经过统一清洗处理——去除多余空白、合并被截断的段落、识别标题层级、处理特殊字符和编码转换。

（二）AI 驱动的智能出题：系统将解析后的文档内容结合用户设定的出题参数（题型、数量、难度、语言等），构建专业的系统提示词和用户提示词，通过 HTTP 请求发送给所配置的大语言模型进行处理。提示词经过精心调优，包含角色定位、输出格式规范、题型示例和具体质量要求。收到 AI 返回的 JSON 数据后，系统进行严格的校验检查，包括 JSON 格式校验、字段完备性检查、选项数量合规检查和答案有效性检查。通过校验的题目被转化为标准化数据结构并保存到题库中。

（三）多种题型支持：系统支持五种标准化考试题型——单选题（四个备选选项，一个正确答案）、多选题（多个正确答案，四至六个备选项）、判断题（陈述真伪判断）、填空题（填写缺失的关键词或短语）和简答题（开放性文字作答）。涵盖从客观到主观的完整题型谱系，满足不同学科和考核目标的出题需求。

（四）题库管理与导出：每次 AI 生成的题目集合自动保存为独立题库，包含唯一标识符、题目列表、创建时间戳和来源文件名等元数据。支持题库重命名、查看、删除等管理操作。支持将题库导出为 XLSX 和 CSV 两种格式，导出内容包含题号、题型、题干、选项、正确答案和解析等完整字段。

（五）在线练习与刷题：内置功能完善的在线练习模块，提供顺序练习、随机练习和模拟考试三种模式。答题界面对每种题型提供适配的交互方式，用户提交答案后系统立即显示判定结果和详细解析。完成所有题目后显示正确率、答题统计等练习结果。练习进度自动保存，支持中断续练。

（六）智能错题管理：系统自动追踪用户在练习中的错误作答，建立错题记录（含累计错误次数、连续正确次数、最近错误时间等）。提供错题本集中查看功能，支持多维排序和条件筛选。错题专项练习模式让用户仅对错题集中攻克。连续答对达到设定阈值（默认 3 次）后自动移除错题，实现智能化的薄弱知识点管理。

（七）安全加密配置存储：在桌面端和移动端应用中，用户的 AI API 密钥等敏感配置信息采用 AES-256-GCM 对称加密算法加密存储，加密密钥通过 PBKDF2 算法从设备特定信息派生。加密配置文件保存在操作系统标准配置目录中，有效防止密钥明文泄露。

（八）多语言界面支持：软件界面完整支持中文（简体）和英文两种语言，用户可在设置页面随时切换，切换后即时生效无需重启。所有界面元素（按钮标签、菜单项、提示信息、错误消息）均提供中英文双语文本。

1.3 适用场景

过了喵适用于多种教育和培训场景。教师出题场景中，教师将教材、课件上传即可快速生成考题，导出为 Excel 进一步编辑和打印，显著减少手工出题的时间成本。学生自测场景中，学生将自己的课堂笔记、教材重点、复习资料上传生成个性化练习题，通过错题本功能高效复习薄弱知识点。企业培训场景中，培训部门将内部培训材料（操作手册、安全规程、产品知识文档等）上传，快速生成员工考核题目，导出的 XLSX 文件可直接导入企业内部学习管理系统。在线教育场景中，教育平台和知识付费创作者可将过了喵集成到内容生产流程，批量生成各章节的配套练习题，大幅提高内容生产效率。自主学习场景中，任何学习者都可以利用 AI 将学习材料快速转化为针对性练习题进行自我检测和知识巩固。专业考试培训机构可以利用系统的高效出题能力加速题库建设，用 AI 生成大量候选题目供教研人员筛选和审核。

1.4 技术架构

过了喵采用前后端分离的现代化软件架构。前端展示层基于 Vue 3 Composition API 构建，使用 Vite 构建工具、TypeScript 类型标注和 Tailwind CSS 样式框架。状态管理采用 Pinia 库，路由管理采用 Vue Router，界面遵循 Material You 设计规范。API 路由层实现运行时平台自动检测——根据运行环境（Tauri 桌面端、Cloudflare Workers 或标准 Web 服务器）自动选择对应的后端通信方式（Tauri IPC 桥接、HTTP Fetch 请求或 Cloudflare Workers Fetch 请求）。后端业务逻辑层使用 Rust 语言编写核心共享库 exameow-core，编译为高性能本地二进制代码。Rust 代码同时复用于 Tauri 桌面应用后端、Axum Web 服务器和独立命令行工具。TypeScript 端提供并行实现以支持 Cloudflare Workers 平台。桌面和移动端壳层基于 Tauri v2 框架，利用操作系统内置 WebView 渲染前端界面，Rust 后端通过 IPC 与前端通信。存储层采用完全本地化策略——Web 浏览器使用 localStorage，桌面端和移动端使用应用专属本地目录，不使用任何外部数据库或云存储服务，从根本上保障用户数据隐私。

第二章 系统要求与安装

2.1 系统运行环境要求

2.1.1 桌面端（Tauri 原生应用）系统要求

桌面端应用以原生二进制程序的形式运行，不依赖 Java、.NET、Python 等外部运行时环境，安装包体积约为 10 至 20MB，安装后占用磁盘空间约 50 至 80MB。各操作系统的具体要求如下：

macOS 系统要求：需要 macOS 10.15（Catalina）或更高版本。推荐使用 macOS 13（Ventura）或更新版本以获得最佳兼容性。同时提供 Apple Silicon（ARM64，适用于搭载 M1、M2、M3、M4 系列芯片的 Mac）和 Intel（x86_64，适用于搭载 Intel 处理器的 Mac）两种架构的安装包，用户应根据自己设备的处理器类型选择对应版本。建议至少配备 4GB 内存和 80MB 可用磁盘空间。运行时需 macOS 的 Aqua 图形界面环境。

Windows 系统要求：需要 Windows 10 版本 1809（Build 17763）或更高版本，或 Windows 11 任意版本。不支持 Windows 7、Windows 8 和 Windows 8.1。提供 x86_64 架构版本。系统需预装 WebView2 运行时——Windows 10 和 Windows 11 系统通常已通过操作系统更新预装 WebView2 运行时，若系统中缺少该运行时，应用安装程序会自动尝试引导安装。建议至少配备 4GB 内存和 80MB 可用磁盘空间。

Linux 系统要求：需要 Linux 内核 5.0 或更高版本，以及 glibc 2.31 或更高版本。需要系统安装有 X11 或 Wayland 显示服务（不支持纯文本终端环境）。必须安装 WebKit2GTK 图形库。在 Ubuntu 或 Debian 系统中，可使用命令 sudo apt-get install libwebkit2gtk-4.1-dev 安装该依赖库。在 Fedora 系统中，可使用命令 sudo dnf install webkit2gtk4.1-devel 安装。在 Arch Linux 系统中，可使用命令 sudo pacman -S webkit2gtk-4.1 安装。此外，部分 Linux 发行版可能还需要 libgtk-3、librsvg、libssl（OpenSSL）等附加库。建议至少配备 4GB 内存和 80MB 可用磁盘空间。

2.1.2 移动端系统要求

iOS 端需要 iOS 14.0 或更高版本，兼容所有支持该版本以上的 iPhone 和 iPad 设备。应用安装包约 15 至 30MB，安装后占用约 40 至 60MB 存储空间。Android 端需要 Android 8.0（API 级别 26）或更高版本，提供 arm64-v8a（适用于绝大多数现代 Android 手机和平板）和 x86_64（适用于部分 Android 模拟器和少数 x86 设备）两种架构版本。依赖 Android System WebView 组件（Android 8.0 及以上系统通常已预装）。APK 安装包约 10 至 20MB，安装后占用约 40 至 60MB 存储空间。

2.1.3 Web 网页版浏览器要求

Web 网页版支持 Google Chrome 90 及以上版本、Mozilla Firefox 90 及以上版本、Apple Safari 15 及以上版本和 Microsoft Edge 90 及以上版本等现代浏览器。浏览器需要启用 JavaScript 功能并支持 WebAssembly（WASM）和 ES2020 及以上 JavaScript 标准。其他基于 Chromium 引擎的浏览器（如 Brave、Opera、Vivaldi 等）通常也可正常使用，但未经过完整测试验证。建议保持浏览器更新到最新版本以获得最佳性能和安全性。

2.1.4 Docker 部署要求

Docker 容器部署需要 Docker Engine 20.10 或更高版本。如果使用 docker-compose.yml 编排文件，需要 Docker Compose 2.0 或更高版本。容器运行至少需要 512MB 可用内存，推荐分配 1GB 或更多。Docker 镜像大小约 100 至 150MB。默认使用 TCP 3000 端口提供 HTTP 服务，需确保宿主机该端口未被其他程序占用且防火墙允许入站连接。容器需要能够出站访问用户配置的 AI API 端点地址。

2.2 桌面端安装指南

2.2.1 macOS 详细安装步骤

第一步——获取安装包：用户通过软件官方渠道获取 macOS 版本的安装包。安装包为 .dmg 磁盘映像格式。根据 Mac 电脑的处理器类型选择对应版本——使用 Apple Silicon 芯片（M1、M2、M3、M4 或更新型号）的 Mac 下载 ARM64 架构版本，使用 Intel 芯片的 Mac 下载 x86_64 架构版本。如不确定自己 Mac 的处理器类型，可点击屏幕左上角苹果菜单，选择"关于本机"，在概览窗口中查看"芯片"或"处理器"信息来进行确认。

第二步——安装应用：在访达（Finder）中找到下载的 .dmg 文件并双击打开。macOS 系统会自动挂载该磁盘映像并弹出一个 Finder 窗口。窗口中包含"Exameow.app"应用图标和一个指向"Applications"（应用程序）文件夹的快捷方式。使用鼠标或触控板将 Exameow.app 图标拖拽到 Applications 文件夹图标上释放，系统将自动将应用复制到应用程序文件夹中。复制进度可以通过 Finder 的复制进度条查看。复制完成后，在桌面或访达侧栏中找到挂载的磁盘映像图标，点击旁边的推出按钮将其卸载。安装完成后，可以在应用程序文件夹或启动台（Launchpad）中找到过了喵应用图标。

第三步——处理首次启动安全提示：首次启动过了喵时，macOS 的 Gatekeeper 安全检查机制可能会显示警告对话框，提示该应用来自未验证的开发者。这是 macOS 对于非 App Store 渠道分发的应用的正常安全检查行为。用户需要执行以下操作来允许应用运行：首先点击警告对话框中的"好"按钮关闭对话框。然后打开"系统设置"应用，在左侧导航栏中找到并点击"隐私与安全性"。在右侧页面中向下滚动至"安全性"区域，在该区域底部可以看到关于 Exameow.app 被阻止使用的记录，旁边有一个"仍要打开"按钮。点击该按钮并输入管理员密码进行确认。之后返回应用程序文件夹，再次双击 Exameow.app 图标启动应用，此时在弹出的警告对话框中点击"打开"按钮即可成功启动。上述操作只需在首次启动时执行一次，后续启动不会再出现安全警告。

第四步——可选操作：当过了喵正在运行时，其图标会出现在程序坞（Dock）中。在程序坞中的过了喵图标上右键点击（或按住 Control 键点击），在弹出菜单中选择"选项"→"在程序坞中保留"，这样即使退出应用后图标也会保留在程序坞中方便下次快速启动。用户也可以将过了喵应用图标从应用程序文件夹拖拽到桌面上创建快捷方式。

2.2.2 Windows 详细安装步骤

第一步——获取安装包：用户通过软件官方渠道获取 Windows 平台的安装包。安装包提供两种格式——.msi 格式（Windows Installer 标准安装包，推荐使用）和 .exe 格式（独立安装程序）。下载其中一种格式的安装文件到本地计算机的下载文件夹或其他方便查找的位置。

2.2.3 Linux 详细安装步骤

方式一——AppImage 格式（推荐）：AppImage 是一种免安装、可直接运行的 Linux 应用打包格式，兼容大多数主流 Linux 发行版。用户从官方渠道下载扩展名为 .AppImage 的安装文件。下载后需要先赋予文件可执行权限——可以通过文件管理器右键点击该文件，选择"属性" → "权限" → 勾选"允许作为程序执行"选项。或者打开终端，切换到下载文件所在的目录，执行命令 chmod +x 文件名.AppImage。赋予执行权限后，双击 .AppImage 文件即可启动过了喵应用，无需进行任何安装操作。如果双击后没有反应，可以在终端中运行 ./文件名.AppImage 来查看可能的错误信息。如果希望创建桌面快捷方式和应用菜单条目，可以考虑使用 AppImageLauncher 等辅助工具，或手动创建 .desktop 文件放置于 ~/.local/share/applications/ 目录下。

方式二——Debian 包格式（适用于 Debian、Ubuntu、Linux Mint 等发行版）：用户从官方渠道下载扩展名为 .deb 的安装包。打开终端，使用 cd 命令切换到下载文件所在的目录，然后执行命令 sudo dpkg -i 文件名.deb 进行安装。如果安装过程中提示缺少依赖包，执行命令 sudo apt-get install -f 让系统自动修复依赖关系。安装成功后，在系统应用菜单中搜索"过了喵"或"Exameow"即可找到并启动应用。

方式三——RPM 包格式（适用于 Fedora、RHEL、CentOS、openSUSE 等发行版）：用户从官方渠道下载扩展名为 .rpm 的安装包。在 Fedora 系统中，可使用命令 sudo dnf install 文件名.rpm 进行安装（dnf 会自动处理依赖关系）。在 RHEL 或 CentOS 系统中，可使用命令 sudo yum localinstall 文件名.rpm 进行安装。安装完成后从系统应用菜单中启动应用。

依赖库安装说明：无论使用哪种安装方式，在 Linux 上运行过了喵都需要确保系统已安装 WebKit2GTK 图形库和其他基础依赖。在大多数现代 Linux 桌面发行版中，WebKit2GTK 通常已经预装。如果启动时提示缺少相关库文件，在 Ubuntu 或 Debian 系统中可执行 sudo apt-get install libwebkit2gtk-4.1-dev libgtk-3-dev libssl-dev librsvg2-dev 来安装所有常见依赖。在 Fedora 系统中可执行 sudo dnf install webkit2gtk4.1-devel gtk3-devel openssl-devel librsvg2-devel。在 Arch Linux 系统中可执行 sudo pacman -S webkit2gtk-4.1 gtk3 openssl librsvg。

4 Docker 容器部署指南

4.1 使用 Docker 运行容器

过了喵提供 Docker 容器化部署方案，用户可以在自有服务器或云服务器上快速部署完整的服务后端。首先确保宿主机已安装 Docker Engine 并正常运行。如果尚未安装 Docker，可根据宿主机的操作系统访问 Docker 官方文档获取安装指引。Docker 安装完成后，在终端中执行以下命令拉取过了喵的 Docker 镜像并创建和启动容器：

docker run -d --name exameow --restart unless-stopped -p 3000:3000 \
  -e AI_ENDPOINT=https://api.openai.com/v1 \
  -e AI_API_KEY=sk-your-api-key-here \
  -e AI_MODEL=gpt-4o \
  exameow:latest

上述命令各参数的含义说明如下：-d 参数使容器在后台运行（不会占用当前终端窗口）；--name exameow 为容器指定一个便于管理的名称；--restart unless-stopped 配置容器在退出时自动重启（除非手动执行 docker stop 命令停止）；-p 3000:3000 将容器的 TCP 3000 端口映射到宿主机的 TCP 3000 端口（如果宿主机 3000 端口已被占用，可修改前面的端口号，如 -p 8080:3000 将服务映射到宿主机的 8080 端口）；-e 参数设置容器内的环境变量，用于配置 AI 服务的连接参数，其中 AI_API_KEY 需要替换为用户实际的 API 密钥。容器成功启动后，在浏览器中访问 http://localhost:3000 即可打开过了喵的 Web 界面（如果修改了映射端口，请使用对应的端口号访问）。如果从局域网内的其他设备访问，将 localhost 替换为运行 Docker 的宿主机的局域网 IP 地址。

第三章 快速入门

3.1 首次启动与 AI 配置

首次启动过了喵后，用户需要完成 AI 服务的基础配置才能使用出题功能。配置流程如下：

步骤一——进入设置页面：启动应用后，在主界面底部导航栏中点击最右侧的"配置"（Config）图标，进入设置页面。

步骤二——填写 AI 服务参数：在设置页面的"AI 服务配置"区域，有三个必填参数需要填写。第一个是 API 端点地址——如果使用 OpenAI 官方服务，填写 https://api.openai.com/v1。如果使用 DeepSeek 服务，填写 https://api.deepseek.com/v1。如果使用阿里通义千问，填写 https://dashscope.aliyuncs.com/compatible-mode/v1。如果使用智谱 AI，填写 https://open.bigmodel.cn/api/paas/v4。如果使用本地部署的模型（如 Ollama），填写 http://localhost:11434/v1。第二个是 API 密钥——从对应 AI 服务商的控制面板中获取的密钥字符串。该输入框默认以密码形式显示（圆点遮挡），可点击旁边的眼睛图标切换内容的显示和隐藏状态。第三个是模型名称——填写要使用的模型标识符，如 gpt-4o、deepseek-chat、qwen-max 等。模型名称必须与 AI 服务商提供的标识完全一致。

步骤三——测试连接：填写完成后，点击"测试连接"按钮。系统将使用所配置的参数向 AI API 端点发送一个简单的测试请求。如果连接成功，界面会显示绿色的成功提示，并自动获取该端点提供的可用模型列表（如果 API 支持模型列表接口）。如果连接失败，请依次检查：API 端点地址的拼写和协议是否正确（注意 https 和 http 的区别）、API 密钥是否已正确粘贴（前后没有多余的空格字符）、网络连接是否正常且能访问目标 API 端点、防火墙或代理是否阻止了连接。

步骤四——保存配置：测试连接成功后，点击"保存配置"按钮。配置信息将被安全地保存到本地存储中。在桌面端和移动端应用中，API 密钥会经过 AES-256-GCM 加密后再存储。配置保存后，后续启动应用时无需重复配置即可直接使用出题功能。

提示：如果还没有 AI 服务提供商的 API 密钥，需要先到对应服务商的官方网站注册账号并获取 API 密钥。大多数服务商提供一定额度的免费试用配额供新用户体验。

3.2 生成第一份考题

步骤一——进入生成页面：点击底部导航栏的"生成"（Generate）图标，进入考题生成页面。

步骤二——上传学习资料：在页面顶部的文件上传区域，用户可以通过点击上传区域打开系统文件选择对话框来选取文件，也可以将文件从系统文件管理器中直接拖拽到上传区域。系统支持 PDF、DOCX、XLSX、PPTX、EPUB、ODT、TXT、CSV、HTML 九种格式。上传成功后，上传区域会显示文件名、文件大小和文件类型图标。如需更换文件，点击"重新选择"按钮清除当前文件后重新上传。

注意：上传的文件不宜过大。建议单个文件不超过 50MB。如果文档内容非常多（如整本几百页的教材），建议按章节拆分为多个文件分别上传和生成，以获得更好的题目覆盖度和生成速度。

步骤三——设置出题参数：文件上传成功后，在参数设置区域设定以下出题参数：题目类型——勾选需要生成的题目类型（可多选），支持的题型有单选题、多选题、判断题、填空题和简答题。题目数量——输入希望生成的总题目数，建议每次生成 5 到 20 道题。数量过多可能影响单题质量。难度等级——从 Easy（简单）、Medium（中等）、Hard（困难）中选择。题目语言——选择生成题目的语言，支持中文和英文。此外还有一个可选的主题过滤输入框，用户可以输入特定主题关键词，让 AI 聚焦文档中与该主题相关的内容出题。

步骤四——开始生成：确认参数无误后，点击"生成考题"按钮。系统将依次执行以下流程：首先解析上传的文档并提取文本内容；然后对提取的文本进行清洗和格式化处理；接着将文本内容和用户参数组合成出题提示词；随后调用 AI 模型生成题目；最后对 AI 返回的题目数据进行 JSON 解析和格式校验。整个过程可能需要几十秒到几分钟，取决于文档大小、题目数量和 AI 模型的响应速度。生成过程中界面会实时显示进度信息。对于内容较多的文档，系统会自动将文本拆分为多个批次依次处理，用户可以查看到每个批次的处理状态。

步骤五——查看结果：生成完成后，应用自动跳转到预览页面，以表格形式展示所有新生成的题目。每行显示题号、题型标签、题干摘要和难度等级。用户可以点击任意题目行展开查看完整的题干文本、所有选项（如有）、正确答案（高亮显示）和详细答案解析。生成的题目已自动保存到题库中，可随时进入练习页面开始刷题。

3.3 开始在线练习

步骤一——进入练习页面：点击底部导航栏的"练习"（Practice）图标，进入练习页面。页面展示所有已创建的题库卡片列表。

步骤二——选择题库：在题库列表中找到目标题库（最新生成的题库排在最前面），点击题库卡片进入该题库。

步骤三——选择练习模式：系统提供三种练习模式供选择。顺序练习——按照题目原始顺序依次作答，适合初次通览所有题目。随机练习——系统随机打乱题目排列顺序，适合多次复习以避免位置记忆效应。模拟考试——需要设定题目数量和考试时长（分钟），系统随机抽题组成考试卷，考试过程中不显示答案判定和解析，更贴近真实考试体验。

步骤四——开始答题：进入答题界面后，系统显示第一道题目。用户根据题目类型进行作答——选择题点击选项按钮提交、判断题点击"正确"或"错误"按钮提交、填空题在输入框中输入答案后提交、简答题在多行文本框中输入文字答复后提交。作答后系统立即显示答案判定结果——绿色表示回答正确，红色表示回答错误——并展示正确答案和详细解析。点击"下一题"继续作答。答错的题目会自动记录到错题本中。完成所有题目后，系统显示练习统计结果，包括总题数、正确数、错误数和正确率百分比，并提供"复习错题"的快捷入口。

文件上传区域位于页面最顶部。未上传文件时，该区域显示为带虚线边框的矩形方框，中央显示上传图标和"点击或拖拽上传文档"的提示文字，用户可以通过点击该区域或拖拽文件到该区域来完成文档上传操作。上传成功后，区域切换为文件预览模式——显示对应的文件类型图标、文件的原始名称和文件的大小信息。预览卡片右上方还有一个"重新选择"按钮，点击可以清除当前文件并重新上传。

参数设置区域位于文件上传区域的下方。该区域以卡片形式呈现，包含以下参数设置控件：题型选择区以一组复选框的形式列出了五种题型（单选题、多选题、判断题、填空题、简答题），用户可以同时勾选多个题型；题目数量输入框用于输入希望生成的总题目数量；难度选择下拉框提供 Easy、Medium、Hard 三个难度级别选项；语言选择下拉框提供中文和 English 两种语言选项；主题过滤输入框为可选项，用户可以在此输入特定关键词，引导 AI 聚焦文档中与该主题相关的内容来出题。

生成进度区在出题流程进行期间显示。当文档被拆分为多个批次处理时，该区域展示每个批次的处理状态——等待中、处理中和已完成——通常以进度条或标签列表的形式呈现，用户可实时了解整体出题进度。

练习页面是用户进行在线刷题和查看学习进度的重要场所。页面默认展示所有可用题库的卡片列表视图。每张题库卡片展示题库名称、该题库包含的题目总数、创建日期时间以及生成该题库时所使用的来源文件名称。空题库状态下（用户尚未生成任何题目），页面显示引导性的提示信息"还没有题库，先生成一些考题吧"，并提供一个可跳转到生成页面的快捷操作按钮。

用户点击任意题库卡片后，进入该题库的详情和模式选择界面。界面展示题库的完整信息以及三种练习模式的选择入口——顺序练习按钮以有序列表图标标识，随机练习按钮以随机排列图标标识，模拟考试按钮以计时器图标标识。选择模拟考试模式时会先弹出一个配置对话框，要求用户设定本次模拟考试的题目数量和考试时长限制。

进入答题后，界面中央显示当前题目卡片。卡片顶部显示进度信息（如当前题号/总题数），中间展示题目类型标签和完整的题干文本，下方根据题型不同展示对应的作答区域——选择题展示可点击的选项卡片组，判断题展示"正确"和"错误"两个大按钮，填空题展示文本输入框，简答题展示多行文本输入区域。用户提交答案后，题目卡片下方立即显示答案判定结果区域——答对时显示绿色背景和正确图标，答错时显示红色背景和错误图标——同时展示正确答案的完整内容和详细的题目解析文本。界面底部设有练习进度条和导航按钮（"上一题"和"下一题"），用户可以在已答题目之间自由导航回顾。在最后一题时，"下一题"按钮自动变为"查看结果"按钮，点击后进入练习结果统计页面。

练习结果页面展示本次练习的综合统计数据——总题目数、正确题数、错误题数、正确率百分比和一个星级或等级评价。统计卡片下方以列表形式逐题展示作答详情，用户可以逐条点击展开查看每道题的完整内容和解析。如果有错题，结果页面还提供"复习错题"的快捷入口按钮，方便用户当即对本次练习的薄弱点进行针对性复习。页面底部设有"返回题库"和"重新练习"两个操作按钮。

4.4 配置设置页面（Config）

配置页面用于管理 AI 服务连接参数和应用的全局偏好设置。页面主要包含以下几个配置功能区域：AI 服务配置区域包含三个输入字段和两个操作按钮——API 端点地址文本输入框、API 密钥密码输入框（附显示切换按钮）和模型名称文本输入框，以及"测试连接"按钮和"保存配置"按钮。外观与语言设置区域包含界面语言下拉选择框（提供中文和 English 两个选项）和主题模式切换开关（支持亮色主题和暗色主题）。关于信息区域展示应用的当前版本号、开发者信息和技术支持渠道。用户在配置页面中做的任何修改都需要点击"保存配置"按钮后才能持久化生效。

4.5 题库预览页面（Preview）

预览页面用于快速查看最近一次生成的所有题目内容。页面以数据表格的形式列出题目——表格列包括题号、题目类型（以彩色标签显示）、题干文本摘要（截取前若干字符）和难度等级（以不同颜色的标签区分）。用户可以点击任意题目行，该行下方展开显示完整内容——包括完整题干、所有选项、正确答案（绿色高亮标注）和详细解析。再次点击可折叠收回。表格上方设有筛选控件——用户可以通过题型下拉菜单和难度下拉菜单对显示内容进行筛选，仅查看特定题型或特定难度的题目。页面右上方设有导出功能的下拉菜单按钮，提供"导出为 XLSX"和"导出为 CSV"两个导出选项。用户还可以通过点击表格列标题对题目进行排序操作。

5.2 上传文档操作步骤

在生成页面顶部的文件上传区域，用户可以通过两种方式上传文档——点击上传区域的任意位置，操作系统将弹出文件选择对话框，在对话框中浏览并选中目标文件后点击"打开"；或者将文件从系统文件管理器直接拖拽到上传区域上释放。上传成功后，区域显示文件图标、文件名和大小信息。如需更换，点击"重新选择"按钮可清除当前文件并恢复初始上传状态。建议单个文件不超过 50MB，大型文档宜分章节上传。

5.3 文档解析原理

过了喵的文档解析模块根据部署平台的不同使用不同的技术实现，但保持解析算法和输出格式的一致性。服务端解析（桌面端、Docker 服务器）由 Rust 语言编写的核心共享库完成。PDF 解析通过读取 PDF 文件内部结构、定位文本流对象并按阅读顺序提取页面内容。DOCX、XLSX 和 PPTX 等 Office 格式文档通过 ZIP 解压后解析内部 XML 结构来提取结构化文本。EPUB 电子书先解析 OPF 清单文件获取书籍元数据和目录结构，再按 spine 顺序提取各章节 XHTML 内容。HTML 和 TXT 文件直接读取文本内容。CSV 文件按行解析行列数据。前端解析（浏览器端、Cloudflare Workers）由 TypeScript 代码完成，实现与 Rust 版本一致的解析逻辑。

提取出的原始文本经过统一的清洗处理流程——去除多余空白和连续空行、合并因分页被截断的段落、识别并保留标题的层级结构和格式信息、处理特殊字符和全角半角字符的编码转换、尝试保留表格数据的行列结构。当清洗后的文本超过约 32,000 个字符时，系统自动在段落或章节边界处将文本切分为多个块，每个块单独发送给 AI 模型进行按比例的题目生成，最终将所有批次的结果合并为完整题目集合。

5.4 注意事项与限制

文档的文本质量直接影响题目生成效果。建议上传文字清晰、排版规范的文档。避免上传纯扫描图片类 PDF（无文本层）、有密码保护或 DRM 加密的文档以及文件已损坏或不完整的文档。系统使用 UTF-8 编码处理文本，能正确处理中文、英文及大多数常见语言文字。PPTX 文件中 SmartArt 图形和嵌入图片中的文字可能无法被完整提取。过于复杂的表格或包含大量合并单元格的表格可能导致解析结果不如预期。EPUB 电子书的封面、版权页等非正文内容会被一并解析但不影响出题质量。

第六章 AI 出题功能详解

6.1 AI 模型配置

过了喵兼容所有遵循 OpenAI Chat Completions API 格式的模型服务。支持的模型包括但不限于 OpenAI GPT 系列（GPT-4o、GPT-4 Turbo、GPT-4o-mini 等）、DeepSeek 系列（DeepSeek-V3、DeepSeek-R1 等）、阿里通义千问系列（Qwen-Max、Qwen-Plus 等）、智谱 AI 系列（GLM-4、GLM-4-Flash 等），以及通过 Ollama、vLLM、LM Studio 等本地部署工具运行的各类开源模型。模型选择建议——追求最佳题目质量推荐 GPT-4o 或 DeepSeek-V3 等旗舰模型，它们在内容理解和指令遵循方面表现最优；注重性价比推荐 GPT-4o-mini 或 DeepSeek-V3；需要完全离线使用且零 API 调用成本时，推荐通过 Ollama 部署本地开源模型。

6.2 题目类型说明

6.2.1 单选题

包含一段题干和四个备选选项（A、B、C、D），仅一个正确选项。适合考查事实性知识的记忆、概念的准确理解和原理的简单应用。系统生成时特别注重干扰项的质量控制——每个干扰项应具有表面上的合理性，对未掌握该知识点的学生而言看起来可能是正确的。解析说明正确选项为何正确以及每个干扰项的错误之处。

6.2.2 多选题

正确答案为两个或更多，备选选项通常四至六个。适合考查多角度知识理解、复合性判断和多条件综合分析。系统确保各正确选项之间的逻辑自洽性。解析逐一说明每个正确选项的合理性。答案以选项键拼接字符串表示（如 ABD）。

6.2.3 判断题

给出一个陈述性语句，要求判断其真伪。适合快速检验知识细节的精确把握和辨别常见误解。陈述内容需具有明确不含糊的真伪判断标准。解析指出判断依据并给出正确的表述形式。

6.2.4 填空题

在题干中设有一处或多处空白位置，要求填写缺失的关键词、短语、数字或公式。适合考查精确的概念记忆和术语掌握。每空设有标准答案，同时考虑语义等价的替代答案。评判采用模糊匹配策略。

6.2.5 简答题

开放性问题，要求以文字形式组织作答。考查知识的深层理解和综合运用能力。系统提供参考标准答案辅助评判，评判采用基于关键词匹配的模糊评分策略。

6.3 难度等级设定

Easy（简单）：考查基础知识的直接记忆和简单理解，题干表述直接清晰，干扰项与正确答案差异明显。适合初次接触新知识时的自测练习和基础概念巩固。中等难度——需要一定的知识理解和综合分析能力，题干可能包含一定的情境描述或多步骤推理，干扰项具有较高的迷惑性。适合常规章节复习和阶段性测验。困难难度——要求深入理解和灵活运用知识，题干可能包含复杂情境或边缘案例，干扰项精心设计以模仿常见误解或易错点。适合高阶学习者、重要考试备考和竞赛训练场景。

Medium（中等）：需要一定的知识理解和综合分析能力，题干可能包含一定的情境描述或多步骤推理，干扰项具有较高的迷惑性。适合常规章节复习和阶段性测验。

Hard（困难）：要求深入理解和灵活运用知识，题干可能包含复杂情境或边缘案例，干扰项精心设计以模仿常见误解或易错点。适合高阶学习者、重要考试备考和竞赛训练场景。

6.4 题目数量与分布

用户输入的总题目数按所选题型数量进行均匀分配。若选择 N 种题型、总数为 T，则每种题型分配约 T/N 道题，余数依次分配给排列靠前的题型。例如选择单选、多选、判断三种题型且总数 10 道时，分配为单选 4 道、多选 3 道、判断 3 道。每个 AI 调用批次最多生成 15 道题目。总数较大时系统自动拆分为多个批次依次处理。

6.5 批量生成机制

当清洗后文本超过约 32,000 字符时，系统在段落或章节边界处将文本切分为多个块。总题目数按各文本块的大小比例分配。各批次按顺序依次调用 AI，避免短时间内大量请求触发 API 速率限制。界面实时显示每个批次的处理进度。所有批次完成后将题目合并为完整集合。

6.6 生成结果查看

生成完成后自动跳转到预览页面，以表格展示所有题目。点击题目行可展开查看完整内容和解析。可通过导出按钮保存为 XLSX 或 CSV 文件，也可直接进入练习模式开始刷题。

第七章 题库管理

7.1 题库浏览与查看

在练习页面可查看所有已创建的题库，以卡片形式展示。每张卡片显示题库名称（默认为生成时间戳，可自定义修改）、题目数量、创建日期和来源文件名。题库按创建时间倒序排列，最新生成的排在最前面。

7.2 题库命名与组织

用户可点击题库名称进入编辑模式，为题库设定有意义的名称以便识别和分类管理。可通过卡片上的删除按钮移除不需要的题库，删除操作前有确认对话框防止误删除。题库的所有数据完全存储在用户本地设备上，保证完全离线可用和数据隐私安全。

7.3 题库导入与导出

通过导出功能可将题库保存为 XLSX 或 CSV 文件进行分享和备份。接收方可将文件导入自己的过了喵中使用。暂不提供自动云端同步功能，用户需手动进行数据的导出备份和跨设备迁移。

第八章 练习模式

8.1 练习模式概述

过了喵提供三种差异化的练习模式以适应不同学习阶段和目标。所有模式共享相同的答题交互和即时反馈机制，但在题目呈现顺序和答题约束方面各有特点。练习模块的设计理念是"练习即学习"——每次答题过程不仅是检验知识掌握程度的手段，更是深化理解和巩固记忆的学习过程。

8.2 顺序练习模式

题目按原始存储顺序依次呈现。适合首次系统性地通览所有题目和按知识体系递进学习。支持"上一题"和"下一题"自由导航，可随时回顾已答题目及其解析。练习进度自动保存，下次进入同一题库时可选择继续未完成的练习或重新开始。

8.3 随机练习模式

每次进入时题目随机排列，避免因反复按固定顺序练习而产生的位置记忆效应。适合多次复习和抽查自测。随机排列由客户端算法实现，不影响原始存储顺序和错题追踪数据。

8.4 模拟考试模式

模拟真实考试场景，用户事先设定题目数量和考试时长。系统从题库中随机抽题组成试卷。考试过程中界面显示倒计时器，不显示答案判定和解析。时间到或主动交卷后统一展示成绩报告和逐题回顾。考试中的错题在交卷后统一记录到错题本。

8.5 答题操作说明

选择题——点击选项卡片或按钮提交答案，单选只能选一个，多选可选多个，已选中的选项高亮显示。判断题——点击"正确"或"错误"大按钮提交答案。填空题——在文本输入框中输入答案后按回车键或点击提交按钮。简答题——在多行文本输入框中输入完整文字答复后提交。

8.6 练习结果统计

完成所有题目后展示详细统计——总题数、正确数、错误数、正确率百分比。逐题回顾列出每道题的作答详情和判定结果。有错题时提供"复习错题"快捷入口。底部提供"返回题库"和"重新练习"按钮。

第九章 错题管理

9.1 错题自动记录

用户在练习中提交错误答案后，系统自动为该题创建错题记录。每条记录包含题目唯一标识符、累计错误次数（每次再错加一）、连续正确次数（用于自动移除机制，每次答对加一、答错归零）、最近错误时间戳和首次加入错题本的日期。错题数据持久化存储在用户本地设备中。

9.2 错题本查看

通过练习页面的"错题本"入口或练习结果页面的"复习错题"入口可访问错题本。错题按最近错误时间倒序排列，每条显示题号、题型、题干摘要和累计错误次数等信息。点击可展开查看完整题目内容和解析。

9.3 错题专项练习

仅对当前错题本中的错题进行集中练习，默认按错误次数从多到少排列。练习中答对的题目不会立即移除——系统追踪连续正确次数，仅当连续正确达到阈值（默认 3 次）时自动移除。再次答错的题目连续正确次数归零并继续留在错题本中。

学习建议：建议完成一轮普通练习后立即进入错题本复习，趁热打铁巩固薄弱知识点。第二天再进行间隔复习，利用遗忘曲线原理加深长期记忆。连续三次正确自动移除的机制避免了在已掌握题目上浪费时间。

9.4 错题排序与筛选

支持多种排序方式——按错误次数降序（最常错的排前）、按最近错误时间降序（刚错的排前）、按添加时间升序（长期未解决的排前）、按连续正确次数升序（即将清零的排前）。支持按题型和来源题库进行筛选显示。

9.5 错题清除机制

自动清除——连续正确次数达到设定阈值时系统自动移除错题。手动清除——逐条删除错题记录。批量清除——一次性清空所有错题，操作前弹出确认对话框。移除后若再次答错同一道题，该题重新加入错题本并从零开始累计数据。

第十章 导出功能

10.1 XLSX 格式导出

XLSX 是推荐的导出格式，能完美保留题目的结构化信息。导出文件包含一个工作表，每行一道题目。列结构为——A 列题号、B 列题型、C 列题目文本、D 至 G 列选项 A 至 D、H 列正确答案、I 列答案解析。在预览或题库详情页面点击导出下拉菜单选择"导出为 XLSX"。系统通过纯代码方式手动构建符合 Office Open XML 标准的 ZIP 压缩包文件，不依赖任何第三方 XLSX 生成库。

10.2 CSV 格式导出

CSV 格式通用性强、文件体积小、兼容性广泛。列结构与 XLSX 相同，列间以逗号分隔。含逗号的字段用双引号括起。使用 UTF-8 编码以正确显示中文字符。在 Excel 中正确打开 UTF-8 CSV 文件需使用"数据"→"从文本/CSV 导入"功能并指定 UTF-8 编码。

10.3 导出内容说明

题型标识对照——single_choice（单选题）、multi_choice（多选题）、true_false（判断题）、fill_blank（填空题）、short_answer（简答题）。答案列格式——单选和多选显示选项字母（如 A 或 ABD），判断显示"正确"或"错误"，填空和简答显示标准答案文本。导出后可在 Excel 或 Google Sheets 中进一步编辑、排版和打印。

第十一章 设置与配置

11.1 AI 服务配置

API 端点地址默认预设为 OpenAI 官方地址 https://api.openai.com/v1。其他常见服务商端点——DeepSeek 为 https://api.deepseek.com/v1，通义千问为 https://dashscope.aliyuncs.com/compatible-mode/v1，智谱 AI 为 https://open.bigmodel.cn/api/paas/v4，本地 Ollama 部署为 http://localhost:11434/v1。API 密钥输入框以密码形式显示，点击眼睛图标可切换可见性。配置页面中设定的参数具有最高优先级，会覆盖启动时通过环境变量设置的参数值。

11.2 模型选择与管理

点击"测试连接"按钮后，如果所连接的 API 服务支持模型列表接口，系统会自动获取并展示可用模型列表，用户可从列表中点击模型名称自动填入输入框。对于不支持列表接口的服务，需手动输入准确的模型标识符。

11.3 加密存储机制

在桌面端和移动端应用中，用户的 AI API 密钥等敏感配置信息采用 AES-256-GCM 对称加密算法进行加密保护。加密密钥通过 PBKDF2 密钥派生算法从设备硬件相关的特定信息中派生，实现了加密密钥与设备的绑定。加密后的配置文件保存在操作系统标准配置目录中——macOS 为 ~/Library/Application Support/Exameow/，Windows 为 %APPDATA%/Exameow/，Linux 为 ~/.config/Exameow/。即使加密的配置文件被复制到其他设备，由于派生密钥不同，也无法解密其中的内容。

安全提醒：API 密钥是访问 AI 服务的重要凭证。建议为过了喵单独创建一个 API 密钥并设置使用额度限制。如怀疑密钥已泄露，请立即在 AI 服务商的控制面板中撤销该密钥并重新生成新的密钥。

11.4 语言切换

在设置页面的外观与语言区域，通过界面语言下拉选择框可切换中文（简体）和 English 两种语言。切换后界面即时生效无需刷新或重启应用。语言切换覆盖所有界面文本元素——导航栏标签、按钮文字、表单标签、提示信息和错误消息。AI 生成的题目内容本身不受界面语言切换影响，题目语言由出题参数中的"题目语言"设置独立控制。系统默认根据操作系统或浏览器的语言偏好设置自动选择初始界面语言。

11.5 主题与外观

过了喵的界面设计遵循 Google Material You（Material Design 3）设计规范。配色方案围绕主色、次要色、第三色和错误色四个色相构建完整的色调阶梯，各界面元素的颜色按照 Material Design 3 的颜色角色规范进行分配。系统同时支持亮色主题和暗色主题——暗色模式下界面背景色切换为深色调以降低在低光照环境下的视觉疲劳。主题模式默认跟随操作系统的主题设置，用户也可以在设置页面中手动指定固定的主题模式偏好。

第十二章 多平台使用指南

12.1 Web 网页版

Web 网页版是通过浏览器直接访问的最简便使用方式，无需安装任何软件。在浏览器地址栏输入部署了过了喵的服务器地址即可访问。Web 版使用浏览器自带的 localStorage 存储机制保存所有用户数据，数据绑定在特定的浏览器和域名上。不同浏览器之间的数据不互通。清除浏览器缓存或站点数据会导致所有题库和练习记录丢失，建议用户定期使用导出功能备份重要数据到本地文件。

12.2 桌面客户端（Tauri）

桌面客户端是功能最全面的使用方式。应用以原生窗口运行，拥有独立的程序图标和系统任务栏条目。文档解析完全在本地计算机上完成，无需将学习资料上传到任何外部服务器。API 密钥经过 AES-256-GCM 加密后安全存储在系统配置目录中。已生成的所有题库和练习功能均可完全离线使用，仅 AI 出题功能需要网络连接以调用云端 AI 服务。导出文件时使用操作系统原生的文件保存对话框，体验流畅自然。

12.3 自托管服务器（Docker）

Docker 部署方式适合团队或组织内部使用。管理员在服务器端统一配置 AI API 密钥，团队成员无需各自配置即可直接使用出题功能。由于数据处理在自有的服务器上完成，能够更好地保护敏感或机密的文档内容。可通过 Docker 的水平扩展部署多个服务实例，配合 Nginx 等反向代理软件实现负载均衡，为更多的并发用户提供稳定的服务。通过 Cloudflare Tunnel 或 FRP 等内网穿透工具，可将部署在内网的 Docker 服务安全地暴露到公网供远程访问。

12.4 Cloudflare Workers 部署

Cloudflare Workers 部署方式利用 Cloudflare 遍布全球的 330 多个边缘计算节点，实现极低的用户访问延迟。平台提供慷慨的免费使用额度（每日十万次请求），对于个人用户和小团队来说完全足够。受 Workers 平台的计算时间限制，超大型文档（数十 MB 以上）建议在桌面端或 Docker 环境中处理。Worker 端的文档解析由 TypeScript 代码在 V8 隔离环境中执行，前端静态资源也同时部署到 Cloudflare 平台。

第十三章 常见问题与故障排除

13.1 文档上传后显示"文件解析失败"

首先检查文件是否已损坏或不完整——使用其他软件尝试打开该文件，确认其可正常读取。其次检查文件是否设置了密码保护或 DRM 加密——过了喵不支持解析受保护的文档文件。对于 PDF 文件，请确认其包含文本层面非纯扫描图片——纯图片扫描版的 PDF 无法提取文字内容，建议先用 OCR 光学字符识别软件将扫描版 PDF 转换为可搜索的文本版 PDF 后再上传。最后检查文件格式是否在支持的九种格式范围内。如果以上检查均正常但仍解析失败，请尝试将文档转换为其他格式（如转存为 TXT 纯文本）后再上传。

13.2 点击"生成考题"后长时间无响应或提示超时

第一步，检查 AI API 密钥是否有效——登录 AI 服务商的控制面板查看密钥的状态是否为活跃（Active）。第二步，检查设备的网络连接是否正常——可尝试在浏览器中直接访问 API 端点地址来确认网络可达性。第三步，检查是否超出了 API 调用的速率限制（Rate Limit）——如果是因为短时间内请求过多被限流，等待几分钟后重试即可。第四步，检查防火墙或代理软件是否拦截了与 AI API 端点的连接。第五步，如果使用 Cloudflare Workers 部署且处理的是大型文档，可能因为超出 Workers 平台的执行时间上限而超时，建议拆分文档或切换到桌面端处理。

13.3 生成的题目质量不理想

提升题目质量有以下建议：升级到更先进的 AI 模型——旗舰模型（如 GPT-4o、DeepSeek-V3）的出题质量显著优于经济型模型。确保上传的文档内容完整、准确、条理清晰——输入文档的质量直接决定输出题目的质量。合理控制题目数量——一次生成过多题目（如超过 20 道）可能导致 AI 为了凑数而降低单题质量，建议每次生成 5 到 15 道题。尝试调整难度参数——有些模型在特定难度级别下的表现更好。如果干扰项质量差（如明显不合理的选项），这是模型能力的反映，建议切换到更强的模型。

13.4 AI 返回非 JSON 格式导致解析失败

这种情况偶尔发生，是因为 AI 模型未严格遵循 JSON 格式的输出指令。解决方案——点击重试按钮重新生成，AI 模型的不确定性意味着重新生成通常会得到正确格式的结果。如果问题频繁出现，建议切换到更擅长结构化输出的模型（如 GPT-4o 的 JSON 模式支持更好）。如果持续出现且无法解决，可能需要考虑更换 AI 模型。

13.5 练习记录或题库数据丢失

在 Web 网页版中，数据丢失最常见的原因是清除了浏览器缓存或浏览历史记录——localStorage 中的数据会随缓存清除一起被删除。使用了浏览器的隐私模式或无痕模式——该模式下所有本地存储数据在关闭窗口后会自动清空。在桌面端中如果是更新或重装了应用可能导致数据目录变更。预防措施——定期使用导出功能将重要的题库和错题数据备份为 XLSX 或 CSV 文件保存到本地磁盘上。

13.6 导出文件在 Excel 中打开出现中文乱码

CSV 格式文件需要使用 Excel 的"数据"选项卡 → "从文本/CSV 导入"功能来打开，在导入向导中选择文件原始编码为 UTF-8（65001），然后加载数据。直接双击 CSV 文件打开可能会导致中文显示为乱码。XLSX 格式文件直接双击打开通常不会出现乱码问题。如果 XLSX 文件也出现乱码，可能是文件在下载过程中不完整，请重新导出一次。

13.7 Docker 容器启动后无法通过浏览器访问

排查步骤——执行 docker ps 检查容器是否正在运行；如果未运行，执行 docker logs exameow 查看容器启动日志以定位问题原因；检查端口映射是否正确（确认 docker run 时使用了 -p 参数）；检查宿主机防火墙是否阻止了目标端口的入站 TCP 连接；尝试使用 http://127.0.0.1:3000 替代 http://localhost:3000 进行访问；如果从其他设备访问，将 localhost 替换为宿主机的局域网 IP 地址。

13.8 macOS 桌面端提示"无法验证开发者"

这是 macOS Gatekeeper 安全机制的正常行为，因为过了喵使用了开发者自签名证书而非 Apple 官方开发者计划签名。解决方案——打开"系统设置" → "隐私与安全性"，在页面底部"安全性"区域中找到被阻止的应用记录，点击旁边的"仍要打开"按钮，输入管理员密码确认。此操作仅在首次启动时需要执行一次，之后不会再出现此安全提示。

13.9 "测试连接"按钮点击后显示连接失败

依次检查以下各项——API 端点地址的拼写是否正确（确认没有多余的空格或拼写错误）、协议是否正确（确认该使用 https 还是 http）、端口号是否包含在地址中（如本地的 Ollama 需要包含 :11434 端口）。API 密钥是否正确粘贴且前后没有多余的空格。网络是否正常——可以在终端中使用 curl 命令测试是否能访问 API 端点。如果使用本地部署的模型服务（如 Ollama），确认该服务已经启动并正在运行。

13.10 填空和简答题的评判标准是什么

填空题采用模糊匹配策略——系统检查用户输入的内容中是否包含标准答案的核心关键词，不完全精确匹配但包含核心关键词的情况可能被标记为基本正确。同义词或等价的不同表述方式也可能被视为可接受的答案。简答题同样采用基于关键词匹配的模糊评分策略——系统提取用户答案中的关键术语和核心概念，与参考标准答案中的关键词集合进行比对。由于简答题的答案具有主观性，建议用户在查看解析时将重点放在内容理解而非精确的匹配程度上。
